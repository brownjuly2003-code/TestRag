# Opus Result Followup: Telegram-Facing Copy

> Источник стилистики: `docs/legal-document-prompts.md §Безопасность и подача`, `opus_result_next_disclaimer.md`.
> Аудитория: сотрудник (HR/legal), русский язык, нейтрально-деловой тон, без emoji-маркеров если они не функциональны.
> Длина: каждое сообщение — одно screen без скролла в Telegram mobile.
> Все формулировки — passive-safe: бот не обещает юридической точности, всегда указывает на необходимость проверки человеком.
> Никакие проектные файлы не редактировались.

## 1. Greeting (после `/start` или первого сообщения)

```
Здравствуйте. Я — демо-ассистент по HR и юридическим вопросам.

Что я умею:
• Отвечать на нормативные вопросы со ссылками на ТК РФ, ГК РФ, ФЗ и приказы.
• Помогать определить тип документа и список недостающих полей.
• Готовить черновики кадровых приказов и договоров на основе утверждённых шаблонов.

Что важно знать:
• Документы в моей базе — синтетические образцы, созданные для демонстрации. Они не являются корпоративными регламентами.
• Ссылки на нормативные акты — реальные, но конкретный ответ всегда сверяйте с юристом.
• Если уверенности недостаточно — я честно отказываюсь отвечать, а не догадываюсь.

Это не юридическая консультация. Финальные документы готовит и проверяет специалист.

Задайте вопрос текстом, я отвечу.
```

### Альтернативный short-вариант (если bot сам шлёт после auth-check, без `/start`)

```
Здравствуйте. Я — демо-ассистент по HR и юридическим вопросам. Отвечаю с ссылками на нормы; черновики документов помечаю как требующие проверки человеком. Корпус документов — демонстрационный, нормативные ссылки реальные. Это не юридическая консультация. Задайте вопрос.
```

## 2. Refusal (refused=true, low confidence или off-topic)

### Вариант A — стандартный refusal

```
В моей базе недостаточно проверенных источников по этому вопросу.

Что можно сделать:
• Переформулировать через номер статьи или закона (например: «ст. 70 ТК РФ»).
• Уточнить категорию документа (трудовой, гражданско-правовой, перевозка, ПДн).
• Обратиться к профильному специалисту, если тема выходит за рамки демо-корпуса.

Я не догадываюсь, когда источников нет.
```

### Вариант B — refusal на out-of-scope тему (например, морские/авиаперевозки)

```
Эта тема не входит в проиндексированную базу демо-корпуса. По морским/авиаперевозкам, узкоспециализированным договорам и международным конвенциям, не указанным в реестре источников, я отвечать не буду — это снизило бы достоверность.

Уточните вопрос или обратитесь к профильному специалисту.
```

### Вариант C — refusal на бессмысленный/слишком общий вопрос

```
Не удалось понять вопрос. Сформулируйте, что нужно узнать, желательно с указанием темы — трудовой договор, отпуск, договор поставки, претензия, путевой лист, ПДн.
```

## 3. Low-confidence answer (refused=false, но `confidence` около порога)

Шаблон постфикса к ответу. Добавляется, когда `MIN_CONFIDENCE <= confidence < HIGH_CONFIDENCE` (порог зависит от настройки RAG API).

```
⚠️ Уверенность ответа ниже обычной. Источников по теме мало, проверьте ответ перед использованием и при необходимости уточните формулировку.
```

Без emoji (если по бренду):

```
[Низкая уверенность] Источников по теме мало. Проверьте ответ перед использованием и уточните формулировку при необходимости.
```

## 4. Feedback confirmation

### После «👍» / good

```
Спасибо за оценку. Ответ помечен как полезный — это поможет улучшить ранжирование.
```

### После «👎» / bad

```
Спасибо, я учту. Ответ отправлен на ручное ревью команде проекта. Если хотите — переформулируйте вопрос, попробую ещё раз.
```

### Если пользователь нажал кнопку дважды

```
Оценка уже учтена. Спасибо.
```

### Если кнопки feedback пришли по устаревшему сообщению

```
Этот ответ уже не активен. Задайте вопрос заново — оценю свежий ответ.
```

## 5. Whitelist denial (user_id не в `ALLOWED_TELEGRAM_USER_IDS`)

### Вариант A — стандартный (рекомендуется)

```
Доступ к боту ограничен списком пользователей.

Ваш Telegram ID: <user_id>

Если вам нужен доступ — передайте этот ID администратору проекта. Демо-бот не открыт для широкой аудитории.
```

> Поведение, описанное в `docs/demo-runbook.md §Whitelist`: бот возвращает user_id и просит добавить его в `.env`. Текст выше — пользовательская форма этого механизма.

### Вариант B — короткий (если bot шлёт без подсказки про ID)

```
Доступ к боту ограничен. Если вам нужно подключение, обратитесь к администратору проекта.
```

## 7. Error / технический сбой (опционально)

Если API недоступен или вернул 5xx:

```
Не удалось обработать запрос — техническая ошибка. Попробуйте через минуту. Если ошибка повторяется, сообщите администратору.
```

Не раскрывать детали ошибки (stacktrace, имя сервиса).

## Wording-rules (для Codex / разработчика)

1. Не использовать слова «гарантирую», «точно», «без сомнений» — только «по моим источникам», «согласно ст. ...», «вероятно».
2. Не упоминать конкретный `confidence` числом в Telegram (внутренний показатель, путает пользователя).
3. Не упоминать имена внутренних сервисов (`/ask`, `mistral`, `pgvector`, `n8n`) — пользовательский язык, без архитектуры.
4. Не печатать `user_id` других людей.
5. Никогда не печатать `MISTRAL_API_KEY`, `TELEGRAM_BOT_TOKEN`, `N8N_WEBHOOK_SECRET` — даже в error-сообщениях.
6. Сохранять формулировку «Это не юридическая консультация» хотя бы один раз в каждой сессии (греетинг + при template_draft).
